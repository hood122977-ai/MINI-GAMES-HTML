# IRONMARCH — Frontier Command

브라우저용 단일 플레이 3D RTS 공성 게임. 기지 건설, 부대 훈련, 드래그 선택, 우클릭 이동/공격, 방벽 충돌, 중립 거점 점령 및 자동 저장을 지원합니다.

## 실행 및 검증

`dist/`를 정적 웹 서버로 서비스합니다. 브라우저 ES modules를 사용하므로 HTML을 파일 URL로 직접 열지 않습니다.

```sh
node --test tests/simulation.test.mjs
```

WebGL2를 지원하면 Three.js가 GPU로 렌더링합니다. 지원하지 않으면 `SoftwareRenderer`가 동일한 모델의 삼각형을 Canvas에 투영합니다. 호환 모드는 그림자와 깊이 표현이 단순하고 많은 유닛에서 느릴 수 있습니다. 외부 CDN 없이 배포된 Three.js 파일을 사용합니다.

## 구조와 SOLID 적용

| 모듈 | 책임 |
| --- | --- |
| `dist/js/core.js` | 데이터 정의, World, EntityFactory, EventBus, 저장소 어댑터 |
| `dist/js/systems.js` | 경제, 생산, 전투, 이동, 영토, 적 공세, 검증된 명령 |
| `dist/js/models.js` | 3D 모델 생성 레지스트리 |
| `dist/js/renderer.js` | 카메라, 장면 표시, 선택 투영, 미니맵 |
| `dist/js/software-renderer.js` | WebGL 미지원 환경의 렌더러 어댑터 |
| `dist/js/input.js` | 선택/건설/공격 입력 모드 및 명령 생성 |
| `dist/js/ui.js` | HUD, 건설·훈련 카드, 안내·결과 화면 |
| `dist/js/main.js` | 의존성 조립과 고정 시간 간격 게임 루프 |

- **SRP:** 경제·전투·생산·이동·영토 규칙을 독립 시스템으로 분리. UI가 전투 피해를 계산하지 않습니다.
- **OCP:** 모델 생성 레지스트리와 피해 전략 등록으로 확장 지점을 제공합니다. 완전히 새로운 행동은 관련 시스템 확장이 필요합니다.
- **LSP:** 피해 전략은 모두 `calculate(attacker, target)` 계약을 지킵니다. GPU/소프트웨어 렌더러는 소비하는 `setSize`, `setPixelRatio`, `render` 계약을 공유합니다.
- **ISP:** 시뮬레이션은 DOM/WebGL을 가져오지 않으며 시스템은 `update(world, dt)`만 제공합니다. 저장소는 get/set/remove 계약만 사용합니다.
- **DIP:** Navigation, 피해 전략, 저장소, 이벤트 버스, 명령 서비스는 생성자로 주입합니다. `main.js`가 구체 구현을 조립합니다.

## 패턴

- **Command:** BuildCommand, TrainCommand, MoveCommand가 검증 및 상태 변경을 수행합니다.
- **Observer:** EventBus가 shot, capture, built, end, notice 등을 전달합니다.
- **Factory / Registry:** EntityFactory와 ModelFactory가 데이터 및 화면 객체를 만듭니다.
- **Strategy:** StandardDamage와 SiegeDamage를 CombatSystem에 주입합니다.
- **Adapter:** SaveRepository 및 SoftwareRenderer가 외부 환경의 차이를 감춥니다.
- **명시적 입력 상태:** select/build/attack 모드. 불필요한 하위 클래스 없이 작은 상태 전이를 유지합니다.

## 게임 규칙

금과 합금은 본진 기본 수입과 생산 기지에서 발생합니다. 각 점령 거점은 금 +5/s, 합금 +3/s와 주변 건설 범위를 제공합니다. 거점 반경 100 안에서 병력이 7초간 점령하면 소유권이 바뀌며 양 진영이 있으면 진행이 멈춥니다. 전초 기지는 영토와 전진 건설 범위를 늘립니다. 영토 표시는 기지·거점의 영향권이며 OpenFront의 셀 단위 공격 시뮬레이션을 그대로 구현한 것은 아닙니다.

최대 아군 병력 80기, 병영당 대기열 8기. 공성차는 건물에 4배 피해. 적 사령부 파괴 시 승리, 아군 사령부 파괴 시 패배. 이전 2D 버전 저장과 호환되지 않으며 새 버전은 별도 저장 키를 사용합니다.

## 참고한 작품과 적용 범위

- [OpenFront](https://github.com/openfrontio/OpenFrontIO): 영토 지배·국경 시인성을 참고. 코드와 에셋을 복사하지 않았습니다.
- [Stronghold: Definitive Edition](https://store.steampowered.com/app/2140020/Stronghold__Definitive_Edition/): 성벽 건설과 공성/방어 역할을 참고.
- [Manor Lords](https://store.steampowered.com/app/1363080/Manor_Lords/): 건설과 경제·전투의 연결을 참고.
- [Age of Empires IV](https://www.ageofempires.com/games/age-of-empires-iv/): 부대 지휘·거점 전투를 참고.
- 사용자가 제공한 SF RTS 이미지: 파랑 진영색, 밝은 금속 건물, 유형별 실루엣의 시각적 방향을 참고. 모델은 코드로 직접 제작했습니다.

## 한계

싱글 플레이 알파입니다. 멀티플레이, 외교, 보병의 성벽 탑승, 수리, 전장의 안개는 아직 없습니다. 40단위 격자 길찾기와 단순 AI를 사용합니다. CPU 호환 렌더링은 정적 지형과 동적 객체를 분리해 그리므로 일부 겹침 표현이 GPU 모드와 다릅니다.

## 대륙 확장 / 03

시작 화면 → 메인 대륙 지도 → 게임 화면으로 전환합니다. 4,800 × 3,200 전장에 6개 출발 지역과 8개 점령 거점을 배치했으며 세 연결 다리를 통해 모든 지역에 도달할 수 있습니다. 지역별 시작 위치와 보급이 다릅니다. 룬테라 참고 이미지의 설산·초원·사막·군도 배치를 참고하되 지형, 지명, 문장과 모델은 직접 구성했습니다.

`geography.js`가 월드맵·길찾기·전장·미니맵에 공통 지형을 공급합니다. `atlas.js`는 지도 표시, `scenes.js`는 씬 상태 전이, `formations.js`는 대열 전략과 부대 등록, `previews.js`는 실제 모델 썸네일과 공통 능력치 툴팁을 담당합니다. 스타크래프트와 워크래프트에서 익숙한 선택·부대 번호·지휘 흐름을 참고했습니다.

- 카드 및 도감: 마우스 오버 또는 키보드 포커스로 체력, 공격력, 사거리, 속도, 비용, 생산 시간을 표시합니다. 실제 게임 데이터 정의를 사용합니다.
- 드래그: 부대 선택. 우클릭: 이동/공격. Q: 전체 병력. F: 공격 이동. X: 정지. V: 위치 사수.
- Ctrl+1~9: 현재 선택을 부대에 등록. 1~9: 부대 호출. UI의 번호 선택+등록 버튼 또는 부대 버튼 우클릭으로도 등록합니다.
- 방진·횡대·종대·쐐기: 다음 이동 목적지에 대열을 배치하고 가장 느린 병력에 이동 속도를 맞춥니다. 장애물을 우회하는 동안은 대열이 풀릴 수 있습니다.
- Space: 일시정지. H: 본진. WASD/화살표: 카메라. 휠: 확대/축소.
- 월드맵으로 나가면 전투를 정지하고 저장합니다. 이어하기는 자원·건물·유닛·거점과 부대 편성을 복원합니다. 지도 확장 이전 저장은 별도 키에 남으며 새 지도에서는 새 원정을 시작합니다.

검증: 11개 시뮬레이션 테스트(생산·전투·저장·6개 시작 위치·전 거점 연결·대열·부대·위치 사수)와 브라우저의 씬 전환·모델 카드·툴팁·부대 등록을 확인했습니다. 검증 브라우저에서는 WebGL 미지원으로 소프트웨어 렌더러를 사용했습니다.

## 지휘 UI 개선 / 04

전장을 9,600 × 6,400으로 확장했습니다(직전 버전 면적의 4배). 육지와 연결 다리, 지역 좌표를 함께 확장했으며 기존 저장의 위치를 변환하고 부대 ID는 유지합니다.

지휘 패널 상단에서 보병·사수·공성차를 각각 선택할 수 있습니다. 개별 병력 목록에서는 클릭으로 한 기, Shift+클릭으로 여러 기를 선택합니다. 선택 병력 위치로 이동(C), 선택 해제, 이동 버튼→땅 클릭을 지원합니다. 명령 설명과 선택 병력 수를 표시하며 선택하지 않았을 때는 명령을 비활성화합니다. 1~3부대를 기본 표시하고 4~9부대와 대열은 펼쳐서 사용합니다.

선택 규칙은 `selection.js`로 분리했습니다. 미니맵의 고정 지형은 캐시해 반복 계산을 줄였습니다. 13개 시뮬레이션 테스트가 통과했으며 브라우저에서 사수 3기만 선택 및 해당 위치로 카메라 이동을 확인했습니다.

## 하단 RTS 콘솔 / 05

사용자 참고 이미지의 3분할 구조를 적용했습니다: 왼쪽 미니맵, 가운데 병력·부대, 오른쪽 선택 대상의 명령. 군사 기지 선택 시 생산 카드, 사령부 선택 시 건설 카드, 유닛 선택 시 이동·공격 명령이 열립니다. 생산 대기열과 기존 모델 툴팁을 유지합니다.

영토의 바닥 색칠·경계선·미니맵 영역 색칠을 제거했습니다. 거점은 보급 수입만 제공하며 건설 허용 조건에서 제외했습니다. 건설은 선택한 아군에서 320 이내, 선택이 없는 명령에서는 사령부 주변을 기준으로 검증합니다. 건물은 즉시 배치되고 방벽은 드래그로 연속 건설합니다. 별도의 건설 시간이나 일꾼 애니메이션은 아직 없습니다.

카메라는 휠 버튼을 누른 채 드래그하거나 전장 내부의 가장자리(18px)에 마우스를 놓아 이동합니다. UI 위에서는 가장자리 스크롤을 하지 않으며 병력 선택/방벽 드래그 중에도 억제합니다. 휠 확대와 C로 선택 병력 위치 이동을 유지합니다.

## 확장 전장과 간단한 분대 조작 / 06

전장은 14,400 × 9,600으로 확장했습니다(05 대비 면적 2.25배). 참고 지도의 분위기를 바탕으로 서부 초승달 육로와 동부 능선 연결을 추가했습니다. 모든 6개 출발 지역에서 8개 거점까지 이동할 수 있으며 기존 저장 좌표를 새 크기로 변환합니다.

군사 기지에서 유닛 생산과 기지 건설 탭을 모두 사용할 수 있습니다. 건설 탭이 명령 탭으로 잘못 연결되던 오류를 수정했습니다. 방벽은 선택 여부와 관계없이 살아 있는 아군 유닛이 설치 지점 320 이내에 있어야 합니다. 건물만 있는 경우 설치할 수 없습니다. 드래그 경로를 40 단위 연속 셀로 보간하고 기존 방벽과 중복되는 비용을 방지합니다.

전체 및 1~9분대 버튼을 상단에 배치했습니다. 분대 버튼 한 번으로 병력을 선택하고 카메라를 이동합니다. 병력 선택 → 분대 등록 → 번호 클릭으로 등록하며 Ctrl+번호도 유지합니다.

검증: 16개 시뮬레이션 테스트 통과. 브라우저에서 지도와 게임 씬 전환, 군사 기지 생산/건설 전환, 5기 분대 등록 및 전체/분대 선택을 확인했습니다.

## 분대별 목록과 편성 / 07

전체 / 1~9분대를 독립된 목록으로 전환합니다. 빈 분대도 열 수 있으며 해당 분대의 유닛 추가 창에서 여러 병력을 골라 추가합니다. 다른 분대 소속 유닛은 중복 편성하지 않고 이동합니다. 전체 또는 분대 목록의 카드를 원하는 분대 버튼으로 드래그해 옮길 수 있고 선택 유닛 빼기로 편성을 해제합니다. 유닛은 삭제되지 않습니다.

SquadPanel은 목록 및 편집 UI를, SquadService는 소속 이동과 해제를 담당합니다. 편집 창에서 전투와 단축키를 잠시 멈추고 닫으면 기존 일시정지 상태를 복원합니다. 기존 저장의 분대 편성을 유지합니다. 시뮬레이션 17개 테스트 통과. 이전 작업 중 브라우저에서 빈 분대 열기, 두 유닛 추가, 목록 필터, 카드 드래그 이동을 검증했습니다.
